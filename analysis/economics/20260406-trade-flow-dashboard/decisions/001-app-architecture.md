# ADR-001: データ取得とアプリ実行の分離

## ステータス
Accepted

## コンテキスト
- BACI の ZIP ファイルは数百 MB あり、毎回ダウンロードするのは非現実的
- Streamlit アプリ起動のたびに生データを処理するのは遅い
- 複数人が同じ環境でアプリを使う場合、事前処理済みデータを共有したい

## 選択肢

| 方式 | メリット | デメリット |
|------|---------|-----------|
| **事前取得 + Parquet キャッシュ（採用）** | アプリが高速。処理を一度だけ行う | データ更新が手動。古くなる可能性 |
| オンデマンド処理 | 常に最新 | 起動が遅い。重複処理が走る |
| DB（SQLite/DuckDB） | クエリが柔軟 | セットアップが複雑。過剰 |

## 決定
事前取得 + Parquet キャッシュ方式を採用する。

処理フロー:
```
1. scripts/download_baci.py  → data/raw/BACI_HS17_V202601.zip をダウンロード
2. scripts/process_baci.py   → ZIP を展開、HS4でフィルタ、Parquet に変換
3. streamlit run app/app.py  → Parquet を読み込んで可視化
```

## 理由
- アプリのレスポンスが速い（@st.cache_data で Parquet をメモリにキャッシュ）
- データ処理とアプリ実装を独立して開発・テストできる
- Parquet はカラム指向で pandas との相性が良く、ファイルサイズも小さい

## トレードオフ・リスク
- データが古くなった場合は手動で再処理が必要（RUNBOOK.md に手順を記載する）
- `data/processed/` も .gitignore に追加し、チームメンバーは各自で処理を実行する
